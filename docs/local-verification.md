# PaperREADed 本机验收

本文区分“程序检查通过”和“真实 AI 分析成功”。不要将模拟模型测试或静态示例当作真实论文分析结果。

## 已有验证及其边界

2026-09-23，PaperREADed 命名及发布准备版本已在 macOS 本机通过：前端 72 项测试、ESLint、TypeScript 生产构建；后端 82 项测试；启动、打包和 HTTP 检查脚本的 25 项测试。数量随代码变化，后续发布仍须重新运行。

使用 Node.js 24.19.0 / npm 11.17.0；后端测试在原有 Python 3.9.10 环境和新建 Python 3.14.5 环境均通过，新环境的锁定依赖安装及 `pip check` 通过。`.python-version` 推荐 3.12，GitHub Actions 配置了 macOS / Ubuntu；远程任务尚未执行，不将它们列为已实测平台。

`scripts/smoke.py` 已实际启动生产前后端并验证首页、证明页、健康接口、同源转发、空白存储及未鉴权拒绝，随后停止服务。验证采用独立临时数据目录，不导入论文、不读取 Codex 登录、不调用真实 AI，也不改变原有论文与分析。

另将白名单源码 ZIP 解压到空目录（不含示例 PDF、私人数据或旧依赖），重新执行 `setup`，前端 72 项、后端 82 项、脚本 25 项测试，以及 lint、生产构建和 HTTP 启动检查均通过。安装时因执行环境不能写默认 npm 缓存，仅为该验证指定临时缓存目录，没有修改系统目录权限。该检查证明本机源码包可独立安装启动，不代表真实 AI 分析已通过。

已有本机检查覆盖：前后端启动、健康检查、静态示例、论文导入和提取、带页码的 PDF 访问、错误与取消状态，以及对外站请求和缺少内部令牌请求的拒绝。测试中的 AI 响应是受控替身，不消耗真实模型配额。

真实 CLI 曾在 Codex 应用的受限执行环境中因 `failed to initialize in-process app-server client: Operation not permitted` 失败。因此，**普通终端中的真实 AI 端到端验收尚未确认完成**。能读取登录状态不等于推理进程一定可以启动。

## 无 AI 检查

建议在干净下载目录测试，不复制旧的 `node_modules`、`.venv`、`.local` 或登录文件：

```bash
python3 scripts/project.py setup
make check
python3 scripts/smoke.py
```

`smoke.py` 自动启动并停止服务，不要求安装或登录 Codex。若需要手动检查界面，再运行：

```bash
python3 scripts/project.py doctor
python3 scripts/project.py start
```

未登录时 `doctor` 会提示，不应被误记为真实 AI 已准备完成。浏览器检查：

- 首页可访问，未登录状态清楚；不要求填写 API Key。
- 导入一篇自己有权处理的带文本层 PDF，文件名、页数与提取结果正确。
- 选择另一份文件后，不允许继续分析旧文件；导入失败时不回退到旧文件。
- 静态示例能显示公式；没有示例 PDF 时不提供失效的原文打开链接。
- `\notin`、分段公式和上下标正常，窄屏公式可以横向滚动而不挤坏页面。
- Ctrl-C 后两个服务退出，再次启动无端口冲突。

## 真实 AI 验收：需本人明确同意

在自己电脑的普通 Terminal 中，用自己的 ChatGPT 账号完成：

```bash
codex login
codex login status
python3 scripts/project.py start
```

1. 在首页导入一篇有权发送的论文，核对文件名及目标编号。
2. 填写明确目标，例如该论文确实存在的 `Theorem 3.1，PDF 第 10 页`，不要照搬别的论文编号。
3. 阅读发送说明，勾选同意后手动开始分析。此步会发送论文提取文本与要求，并消耗自己的 Codex 配额。
4. 确认任务真实完成、结果对应所选论文与目标，而不是 benchmark；抽查陈述、公式、证明依赖及页码。
5. 刷新确认结果仍在；再换论文，确认任务和历史记录没有串文件。

记录系统和运行时版本、日期、代码版本（如有）、目标、成功或失败阶段。不要记录凭据、未授权原文或私人路径。失败时保留脱敏错误，不绕过沙箱、不复制凭据、不将模拟响应改标为真实结果。
